# 文化宫四层当前负荷与年度能耗计算审计报告设计

## 1. 目标

基于 `users.db` 中报告 `BIM-20260714-8219` 的实时记录、当前 `energy_calc.py` 公式和网站参数传递路径，形成一份项目内部使用的 Markdown 技术报告。报告需要回答四个问题：

1. 当前网站设置了哪些参数；
2. 哪些值来自用户输入、程序默认、程序派生或人工核对；
3. 网站如何逐步得到冷热需求、设备用能和全年总用电；
4. 缺失、假设或尚未建模的参数会如何影响结果及可信度。

报告不是规范设计负荷计算书，不把 HDD/CDD 年度模型或等效峰值描述成严格设计负荷。

## 2. 输出

- 文件：`docs/文化宫四层_当前负荷与年度能耗计算审计报告_2026-07-15.md`
- 格式：UTF-8 Markdown，可在 Codex、VS Code 或常见 Markdown 查看器中直接阅读。
- 语言：中文。
- 计算基准：数据库报告 `BIM-20260714-8219`，记录时间 `2026-07-15 06:31:19`。

## 3. 证据优先级

1. 当前数据库 `users.db` 中目标报告的 `params` 与 `results`；
2. 当前 `energy_calc.py` 实际执行公式；
3. `web_server_server.py` 的请求参数、默认值和数据库保存路径；
4. 文化宫图纸和既有交接文档中已人工核实的数据；
5. 页面展示逻辑，仅用于解释用户看到的结果，不反向替代后端计算事实。

若证据之间冲突，报告同时列出原值、实际参与计算的值和冲突原因，不静默选择其中一个。

## 4. 参数分类规则

每个参数归入以下一种来源类型：

- **显式设置**：数据库 `params` 中保存、且来自当前页面输入或选择；
- **人工核实**：根据文化宫图纸或报告核实后录入；
- **程序默认/假设**：缺少项目实测值时由页面或后端提供；
- **程序派生**：由其他输入计算得到，例如人数、新风量、年运行小时；
- **缺失/未建模**：当前没有可靠输入，或公式尚未包含该物理过程；
- **口径错误/不适用**：虽已设置，但不符合文化宫四层实际，例如 VRV 制冷系统。

参数表至少给出：参数、当前值、单位、来源类型、实际用途、可信度、缺失或误设影响。

## 5. 报告结构

### 5.1 执行摘要

说明当前结果、可用范围、主要风险和最优先修正项。明确四层只供暖、不供冷；当前制冷需求和制冷用电不得用于四层原设计对比。

### 5.2 计算对象和模型边界

说明面积 `639.48 m²`、层高 `6.0 m`、顶层、精确围护结构模式，以及 HDD/CDD 年度简化模型的适用范围。

### 5.3 参数总表

分为几何、围护结构、气候、运行、新风与渗透、冷热源、照明、设备和生活热水九组。区分数据库原始几何、精确模式人工几何和最终实际参与计算的几何。

### 5.4 逐步计算链

按以下顺序展示公式、代入值、单位和结果：

1. 面积、人数、运行小时和新风量；
2. 分朝向墙窗 UA、屋面 UA、地面 UA、外门 UA；
3. HDD/CDD 和设定温度修正；
4. 围护结构年度供暖/制冷热需求；
5. 新风显热与渗透风热需求；
6. 年度供暖/制冷热需求汇总；
7. 等效峰值校核及其限制；
8. 供暖、制冷、风机、照明、插座设备和生活热水用能；
9. 全年总用电量和单位面积用电量。

所有复算结果与数据库 `results` 对照。舍入差异单独说明。

### 5.5 数据矛盾与不适用设置

至少检查并解释：

- 四层无供冷，但数据库配置 `vrv`；
- 顶层屋面在主几何中启用，但 `detailed_envelope.roof.included` 保存为 `false`；
- 数据库原始 AI 几何墙窗面积很大，但精确计算实际使用人工分朝向面积；
- 原始几何包含外门面积，而分朝向精确输入的外门面积均为零；
- 运城项目目前使用西安气候数据。

### 5.6 缺失参数影响矩阵

对每个缺失或假设项说明：影响的公式、可能造成结果偏高或偏低的方向、当前能否判断净影响、风险等级和建议证据来源。至少覆盖：

- 运城逐时或逐日气象；
- 真实渗透风/ACH；
- 热回收配置及效率；
- 实际供暖运行日程；
- 四层真实人员密度；
- 实际照明和插座设备功率密度；
- 供暖系统形式、部分负荷性能和季节效率；
- 太阳得热对供暖的抵消；
- 新风制冷潜热；
- 热桥、外门开启、相邻非供暖空间和间歇附加；
- 建筑热惰性和逐时负荷耦合。

### 5.7 可信度分级和改进顺序

分别评价：几何与围护参数、年度供暖热需求、年度供暖设备用能、非暖通用电、制冷结果、等效峰值。给出高、中、低或不适用等级及理由。

改进顺序遵循：先修正供冷口径，再核实渗透风和运行参数，再引入运城逐时气象，最后考虑动态热模型或 EnergyPlus。

## 6. 计算与写作约束

- 不新增或修改网站计算代码；
- 不修改数据库记录；
- 不把缺失值填成看似精确的数字；
- 不用任意调参拟合 `39.43 kW`；
- `kWh_th/a`、`kWh/a` 和 `kW_th` 始终分开；
- 对无法判断偏差方向的因素明确写“方向不确定”；
- 不暂存、提交、推送或部署。

## 7. 验收标准

报告完成时应满足：

1. 数据库中的主要输入和输出均能在报告中定位；
2. 关键结果可由报告中的公式和代入值复算；
3. 所有默认值和缺失项均有明确标记；
4. 明确指出四层制冷结果当前不适用；
5. 明确区分年度能耗、年度热需求和设计峰值；
6. 给出可执行的参数补充优先级；
7. 不含凭证、密码、服务器地址或其他敏感信息。
