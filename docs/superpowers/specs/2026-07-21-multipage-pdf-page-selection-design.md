# 多页 PDF 页码选择设计

## 目标

PDF 只上传一次。多页 PDF 在 AI 识别前让用户选择目标页，之后矢量解析、比例尺标定、页面渲染和房间识别始终处理同一页。

## 用户流程

1. 用户选择或拖入 PDF。
2. 前端把 PDF 上传到预检接口，后端将文件保存到当前报告目录并返回不可伪造的文件标识、文件名和总页数。
3. 单页 PDF 直接使用第 1 页开始识别；多页 PDF 显示页码下拉框和“开始识别”按钮。
4. 用户选择页码后，识别接口引用已上传文件，不再次传输 PDF。
5. PNG/JPG 保持原有选择后直接识别的流程。

## 后端设计

- 新增 `POST /energy/pdf_prepare`，接收 `raster_file` 和 `report_number`。
- 使用 `pdfplumber` 读取页数，拒绝空文件、非 PDF 和无法打开的 PDF。
- 文件保存为报告目录下的固定暂存名称；响应返回由服务端签名的 `upload_token`、`page_count` 和安全文件名。
- `POST /energy/ai_recognize` 支持 `pdf_upload_token` 和 1 起始的 `pdf_page_number`。服务端验证令牌、报告编号、文件存在性及页码范围。
- PDF 的 `extract_vector_page` 使用 0 起始索引，`pdf2image.convert_from_path` 使用 1 起始页码；两者由同一个已校验页码派生。
- `recognition.json` 和识别响应保存 `pdf_page_number`、`pdf_page_count`，非 PDF 对应字段为空。

## 前端设计

- PDF 预检期间显示加载状态。
- 多页 PDF 显示“共 N 页”和页码下拉框，用户确认后开始识别。
- 重新选择文件会清除旧令牌和页码状态。
- 不加入缩略图，不引入 PDF.js，不允许用户填写超出范围的页码。

## 错误处理

- 预检失败时保留在上传步骤并显示中文错误。
- 令牌无效、文件不存在、报告不匹配或页码越界均返回 400，不回退到第 1 页。
- 单页 PDF 与图片上传保持低操作成本。

## 验证

- 两页合成 PDF：预检返回 2 页，选择第 2 页时矢量提取与渲染均收到第 2 页。
- 页码 0、超过总页数、令牌被篡改、令牌与报告不匹配均被拒绝。
- 模板测试确认多页选择控件及两阶段请求存在。
- 完整单元测试、Python 编译和前端 JavaScript 语法检查通过。
