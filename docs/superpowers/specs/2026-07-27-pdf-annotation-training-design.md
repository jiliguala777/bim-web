# 通用 PDF 标注与单页微调训练设计

日期：2026-07-27
状态：待用户最终审阅

## 1. 背景

当前网站已经支持多页 PDF 选页、PDF 渲染、矢量文字和线段提取、尺寸标注清理、建筑 ROI、ONNX 语义分割、比例尺标定和房间拓扑修复。现有独立标注工具仍以 PNG/JPG 和旧版 PyTorch 预标注脚本为中心，不能完整复现网站的 PDF 输入链路。

如果标注工具和网站使用不同的页面渲染、清理或模型输入规则，人工标注生成的数据就不能准确代表生产识别输入。本设计将标注工具代码迁入 `G:\bim-web\annotation_tool`，并为标注结果提供独立训练、评估和 ONNX 导出工具。

首个验收场景是一个四层建筑的一层：人工标注一层，使用同一页微调，再用同一 PDF 页比较新旧模型识别结果。

## 2. 目标

第一版必须完成以下闭环：

```text
导入多页 PDF
→ 选择一层所在页
→ 复用网站预处理
→ 当前 ONNX 模型预标注
→ 人工修正并确认
→ 导出训练数据
→ 从当前 PyTorch checkpoint 微调
→ 导出新 ONNX
→ 新旧模型与人工标注对比
→ 本地网站使用新模型重新识别同一页
```

第一版的核心目标是验证标注、训练、导出和网站加载链路能够闭环。由于训练页和测试页相同，本次结果只证明模型对该页的拟合能力，不作为泛化能力结论。

## 3. 非目标

第一版不包含：

- 在标注网页进程内执行模型训练；
- 自动替换网站默认模型或生产服务器模型；
- 公网标注入口、多人协作和标注账号系统；
- 自动推送图纸、标注数据或模型到 GitHub；
- 用单页实验结果宣称模型对其他建筑图纸也已改善；
- 将构件骨架标注改为完整墙体区域语义标注。

## 4. 代码与数据位置

### 4.1 仓库内代码

```text
G:\bim-web\
├─ annotation_tool\              本地 PDF 标注网页
├─ training\                     独立微调、评估和导出工具
```

标注工具只监听 `127.0.0.1`，不注册到生产网站的公网路由。

### 4.2 仓库外数据

```text
G:\bim网页\标注数据\
├─ sources\                      原始 PDF
├─ projects\                     项目、选页和预处理产物
├─ annotations\                  人工 mask 和版本
├─ exports\                      可训练数据集
└─ models\                       实验 checkpoint、ONNX 和报告
```

现有 `G:\bim网页\标注工具\data` 保持不变，第一版只读兼容，不自动迁移或覆盖其中的 219 张图和标注。

仓库 `.gitignore` 必须排除所有外部数据映射、临时页面、mask、PDF、训练 checkpoint 和导出模型。

## 5. 总体架构

### 5.1 共享预处理模块

从现有网站流程中整理一个可复用、可测试的页面准备接口。网站和标注工具必须调用同一个接口，不能各自复制近似实现。

输入：

- PDF 文件路径；
- 1-based 页码；
- 渲染和预处理配置版本。

输出：

- 页面总数；
- 原始渲染页；
- 清理后的高清页面；
- 建筑 ROI；
- 模型使用的黑底图；
- 512×512 letterbox 模型输入；
- 尺寸标注、非结构和结构支撑 mask；
- 页面、DPI、缩放、padding、ROI 和预处理版本元数据。

当前网站仍使用固定 `[1, 3, 512, 512]` ONNX 输入。第一版必须与当前生产行为一致，保留完整页面上下文和 ROI 外预测清理规则，不在本次工作中擅自切换到分块推理或 ROI 裁剪推理。

### 5.2 PDF 项目管理

每个 PDF 以 SHA-256 识别。重复导入时复用已有来源文件并提示用户，不产生不受控副本。

项目记录：

- 项目名称；
- 源 PDF 哈希和原始文件名；
- 页面总数；
- 已选择页面；
- 每页处理状态；
- 当前预处理版本；
- 当前预标注模型版本；
- 人工确认状态。

页面选择界面提供缩略图和页码。单页失败不会阻断其他页面。

### 5.3 模型预标注

标注工具直接调用网站当前 ONNX 模型，不再依赖旧的 `preannotate.py` 和 PyTorch GUI 环境。

预标注保存为草稿，状态为 `preannotated`。预标注失败时允许从空白 mask 开始，但必须记录失败原因。只有用户执行“人工确认”后，页面状态才变为 `confirmed`。

### 5.4 人工标注界面

界面提供：

- 原始 PDF 渲染页；
- 清理后高清页；
- 黑底模型图；
- 512×512 模型输入和最终 mask 预览；
- 缩放、平移、画笔、橡皮擦；
- 墙、窗、门类别；
- 撤销、重做、自动保存和显式人工确认；
- 类别显示开关和透明度控制；
- 页面处理和保存状态。

标注在高清页面坐标系中保存，同时根据预处理元数据确定性地产生 512 mask。mask 缩放必须使用最近邻插值。

## 6. 标注口径

第一版采用与现有模型兼容的构件骨架粗线标注：

- `0`：背景；
- `1`：墙；
- `2`：窗；
- `3`：门。

规则：

- 墙沿中心连续绘制，在 512 预览中保持约 4～6 像素宽；
- 窗标完整窗洞跨度，并覆盖相应位置的墙类别；
- 门标门洞位置，不标完整开启弧线，并覆盖相应位置的墙类别；
- 文字、尺寸线、轴线、家具、洁具、填充图案和图框均为背景；
- 三个构件类别互斥；
- 墙体连接位置优先保证连续，避免无意产生房间缺口；
- 高清画笔宽度由当前页面到 512 模型空间的缩放比例换算。

第一版不把完整墙体轮廓填充与骨架粗线标注混合。未来如果改用完整区域语义标注，必须建立独立的数据规范和数据版本。

## 7. 标注质量检查

保存和确认前检查：

- 原图和 mask 尺寸匹配；
- mask 只包含 `0..3`；
- 缩到 512 后是否有构件消失；
- 墙体是否存在明显非预期断裂；
- 墙、窗、门像素比例是否异常；
- 没有门或没有窗时要求用户显式确认；
- 页面预处理版本是否与当前项目版本一致。

质量检查默认给出警告，不擅自修改人工 mask。严重格式错误阻止确认和训练导出。

## 8. 持久化和版本

每个已选择页面保存：

```text
page_render.png
cleaned_page.png
model_view.png
model_input_512.png
mask_full.npy
mask_512.npy
mask_preview.png
metadata.json
```

`metadata.json` 至少包含：

- 源 PDF SHA-256；
- 原始文件名和页码；
- 页面总数；
- 渲染 DPI；
- 原始尺寸；
- ROI；
- resize scale 和 letterbox padding；
- 预处理版本；
- 预标注模型名称和模型文件 SHA-256；
- 类别定义；
- 标注状态和更新时间；
- mask 文件 SHA-256。

每次覆盖保存前保留上一版 mask。自动保存产生草稿，显式确认产生不可静默覆盖的确认版本。

## 9. 训练数据导出

训练导出默认只包含 `confirmed` 页面。导出过程重新校验图像、mask、元数据和哈希。

单页实验导出目录包含：

```text
images\floor_1.png
masks\floor_1.npy
manifest.json
dataset_report.json
```

`manifest.json` 明确记录这是 `single_page_overfit` 实验，不创建虚假的随机训练/验证划分。

## 10. 独立训练模块

训练环境与网站运行环境隔离：

```text
G:\bim-web\.venv-train
```

`training\setup_training_env.ps1` 安装受约束版本的 PyTorch、segmentation-models-pytorch、Albumentations、ONNX 和 ONNX Runtime。训练脚本不得改变网站 `.venv`。

训练入口示例：

```powershell
.\.venv-train\Scripts\python.exe .\training\train_floorplan.py `
  --dataset "G:\bim网页\标注数据\exports\四层建筑一层" `
  --checkpoint "G:\bim-web\models\M2_pub_plus_user.pt" `
  --experiment "四层建筑一层单页拟合"
```

训练行为：

- 严格重建 `smp.Unet("resnet34", encoder_weights=None, in_channels=3, classes=4)`；
- 从当前 `M2_pub_plus_user.pt` 加载权重，不从零训练；
- 使用与网站一致的 512 输入和归一化；
- 使用 Dice 与加权交叉熵组合损失；
- 对单页应用可复现的数据增强；
- 以低学习率微调并支持早停；
- 每次实验使用固定随机种子；
- 保存最后模型和最佳模型；
- 记录每类 Dice、IoU、混淆矩阵、损失和训练参数；
- 不覆盖输入 checkpoint 或网站默认 ONNX。

单页数据不能形成独立验证集。最佳模型的选择依据训练页的预设拟合目标和损失稳定性，同时在报告中明确标记这些指标是训练页指标。

## 11. ONNX 导出与对比

训练完成后自动：

1. 导出固定输入 `[1, 3, 512, 512]` 的 ONNX；
2. 运行 ONNX checker；
3. 比较 PyTorch 与 ONNX logits 数值误差；
4. 检查 argmax 像素一致率；
5. 用旧模型和新模型分别推理同一个一层模型输入；
6. 生成旧模型、新模型、人工标注的并排对比；
7. 输出墙、窗、门各自 Dice 和 IoU。

实验输出：

```text
G:\bim网页\标注数据\models\four-floor-building-floor1-overfit\
├─ best.pt
├─ last.pt
├─ best.onnx
├─ training_log.csv
├─ metrics.json
├─ export_report.json
├─ old_model_overlay.png
├─ new_model_overlay.png
├─ ground_truth.png
└─ comparison.png
```

## 12. 本地网站复验

新模型仅通过环境变量临时接入本地网站：

```powershell
$env:ONNX_MODEL_PATH="G:\bim网页\标注数据\models\four-floor-building-floor1-overfit\best.onnx"
.\start_local.ps1
```

重新上传同一 PDF 并选择同一页。比较：

- 最终叠加图；
- 墙、窗、门分别的识别效果；
- 墙体连续性；
- 房间拓扑闭合情况；
- 新旧模型执行时间；
- 人工标注与模型 mask 的类别指标。

确认新模型表现前，不修改仓库默认模型路径，不替换生产模型，不部署服务器。

## 13. 错误处理与安全

- 工具仅监听 `127.0.0.1`；
- 文件路径必须限制在配置的数据根目录内；
- PDF 只读保存，页面产物写入项目目录；
- 不接受路径穿越或任意服务器文件读取；
- 页面渲染、OCR、矢量提取、预标注和保存错误分别记录；
- 临时文件使用原子替换，避免中断后留下半写文件；
- 训练开始前检查可用内存、设备和磁盘空间；
- CUDA 不可用时允许 CPU 训练，但明确提示预计更慢；
- 训练、ONNX 导出或比较失败时保留日志和最后可用 checkpoint；
- 所有模型输出使用新实验目录，不覆盖当前模型。

## 14. 测试策略

### 14.1 单元测试

- PDF 哈希和重复导入；
- PDF 页数和选页边界；
- 网站与标注工具预处理逐像素一致；
- ROI、resize 和 padding 元数据；
- full mask 到 512 mask 的最近邻转换；
- mask 类别和尺寸校验；
- 草稿、自动保存、确认和历史版本；
- 训练导出只包含人工确认页面；
- checkpoint 结构严格加载；
- PyTorch/ONNX 数值一致性；
- 输出目录不覆盖既有文件。

### 14.2 集成测试

- 导入一个测试多页 PDF；
- 选择指定页并生成全部页面产物；
- 使用测试 ONNX 生成预标注；
- 修改并确认 mask；
- 导出单页训练集；
- 运行短周期 CPU 微调；
- 导出 ONNX 并生成比较报告；
- 通过 `ONNX_MODEL_PATH` 启动本地网站并加载新模型。

### 14.3 浏览器验收

使用真实四层建筑 PDF 的一层完成一次端到端人工操作，确认缩放、平移、绘制、撤销、重做、自动保存、重新打开、512 预览和确认导出均可用。

## 15. 第一版验收标准

第一版完成必须同时满足：

1. 升级后的工具位于 `G:\bim-web\annotation_tool`；
2. 图纸和标注数据位于仓库外；
3. 能导入多页 PDF 并选择一层；
4. 标注工具与网站生成完全一致的模型输入；
5. 当前 ONNX 能生成预标注；
6. 能按骨架粗线规范人工修正并确认；
7. 能导出合法的单页训练数据；
8. 独立训练环境能从现有 checkpoint 完成微调；
9. 能导出通过一致性验证的新 ONNX；
10. 能生成新旧模型和人工标注的对比报告；
11. 本地网站能通过环境变量加载新 ONNX 并重新识别同一页；
12. 现有 219 张数据、当前模型和生产服务器均未被覆盖或修改。
