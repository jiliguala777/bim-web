# BIM Web 平台总说明书设计

## 背景

当前根目录 `README.md` 主要记录围护结构材料库和检测报告批处理工作，
不能完整说明平台已经实现的图纸识别、房间闭合、材料选择、负荷计算、年度
能耗、本地开发和服务器发布能力。腾讯云生产环境已经成功运行，因此需要一份
与当前代码和部署现状一致的总说明书。

## 目标读者

- 项目所有者：了解平台完整链路、数据位置、操作步骤和发展路线；
- 开发维护人员：搭建本地环境、修改代码、测试和发布；
- 服务器维护人员：更新程序、替换模型、验证服务、备份和回退；
- 后续协作者：快速理解目录结构、模块职责和安全边界。

README 不作为普通终端用户的逐屏操作教程，也不展开检测报告批处理的历史
进度细节。相关内容通过专题文档保留。

## 文档分层

### 根目录 README

`README.md` 是平台的总入口和日常说明书，必须在不依赖其他文档的情况下讲清：

1. 项目定位、状态和技术栈；
2. PDF 图纸到负荷及年度能耗的完整业务链路；
3. 系统组件、数据流和关键模块；
4. 本地安装、启动、账号配置和测试；
5. 项目目录及主要文件职责；
6. GitHub、本地和服务器的数据存放边界；
7. 日常开发、提交、发布和服务器更新；
8. ONNX 模型更新、校验、权限、切换和回退；
9. 运行维护、日志、备份、安全和故障排查；
10. 当前限制、验收基线和后续路线图；
11. 相关专题文档入口。

### 部署专题

`deploy/README.md` 保留首次部署的完整命令，并同步实际生产环境：

- Ubuntu 24.04 LTS；
- Python 3.12；
- Nginx、Gunicorn、Poppler；
- OpenCV 运行依赖 `libgl1`；
- 代码目录所有者为 `bimweb`；
- 仓库 Git 命令必须通过 `runuser -u bimweb -- git -C ...` 执行；
- 不给 root 配置全局 `safe.directory`；
- 模型不进入 GitHub，单独上传并校验。

### 材料数据专题

将旧 README 中原始报告、分类目录、批处理脚本、处理进度和后续入库流程迁移到：

```text
docs/材料库数据整理与来源处理.md
```

根 README 只说明材料库对平台的作用、正式数据库路径、主要库用途、数据来源
原则和专题文档链接。

## 根 README 信息架构

### 1. 项目概览

说明 BIM Web 是 Flask 建筑图纸识别与能耗计算平台，当前已能通过公网运行。
避免把原型能力描述成经过工程认证的正式审图或法定能耗软件。

### 2. 完整业务流程

用 Mermaid 流程图表达：

```text
登录 → 上传多页 PDF → 选择页面 → 图像/矢量预处理 → ONNX 分割
→ 拓扑修复与房间闭合 → 比例尺和建筑几何 → 材料/系统参数
→ 设计负荷 → 年度冷热需求与用电量 → 保存结果
```

每一步补充对应模块和输出，不只展示流程名称。

### 3. 能力和限制

分别列出当前已验证能力和限制。已验证基线包括文化宫 PDF 第 13 页：

- 模型输入 `[1, 3, 512, 512]`；
- 类别为 `background`、`wall`、`window`、`door`；
- `dominant_span_rectangle` 闭合；
- 19 个房间；
- 总面积约 `1318.78 m²`。

该结果作为部署回归样例，不宣传为所有图纸的通用精度保证。

### 4. 组件和文件职责

使用表格说明入口、识别、OCR、比例尺、房间、拓扑修复、材料库、负荷、
年度能耗、模板、静态资源、测试、工具和部署文件。只列长期维护需要理解的
文件，批量研究脚本在专题文档中分组说明。

### 5. 数据位置

使用对照表明确：

- GitHub：代码、模板、测试、正式材料库、部署模板和文档；
- 本地但不入 Git：模型、上传结果、运行数据库、环境变量和研究原始数据；
- 服务器：应用、虚拟环境、模型、用户库、上传结果和环境文件的绝对路径。

### 6. 开发与测试

以 Windows PowerShell 和项目 `.venv` 为本地标准环境。说明环境变量、依赖
安装、启动脚本、默认地址和 `unittest` 全量测试命令。不得把 `pytest` 写成
标准验收命令，因为当前环境没有安装它。

### 7. 发布和更新

统一采用：

```text
本地 main → origin/main → /opt/bim-web/app
```

明确禁止未审核的 `git add .`，要求发布前查看差异并运行测试。服务器 Git
操作使用 `bimweb`，然后按需安装依赖、重启 systemd、检查日志和浏览器验收。

### 8. 模型生命周期

推荐版本化模型文件名，不直接覆盖旧模型。说明：

1. 本地 SHA-256；
2. 上传到 `/tmp`；
3. 移到 `/opt/bim-web/models`；
4. 设置 `bimweb:bimweb` 和 `0640`；
5. 服务器 SHA-256；
6. ONNX Runtime 加载验证；
7. 修改 `ONNX_MODEL_PATH`；
8. 重启和状态接口验证；
9. 通过旧路径快速回退。

如果输入尺寸、类别或预处理发生变化，必须同步更新代码并运行回归测试。

### 9. 运维、安全和备份

解释 Nginx、Gunicorn、systemd 的职责，列出常用状态和日志命令。明确：

- 不在文档或 Git 中写入真实 IP、密码、私钥、Token 和 `SECRET_KEY`；
- `users.db` 和 `uploads` 在代码目录之外；
- 更新数据库结构或正式材料库前先备份；
- 当前通过 HTTP 公网访问，正式长期使用建议配置域名和 HTTPS；
- 开放注册、数据清理和备份策略需要持续完善。

### 10. 路线图

按近期、中期和长期记录方向，不承诺未实现功能：

- 近期：自动更新脚本、备份、HTTPS、发布检查；
- 中期：识别编辑与人工复核、更多图纸回归、材料库质量提升；
- 长期：多楼层/多区域模型、计算审计、版本化模型和更完善的仿真接口。

## 内容事实来源

1. 当前代码、环境变量和部署模板；
2. 已通过的自动测试；
3. 腾讯云实际验收结果；
4. 现有设计、计划和交接文档；
5. 旧 README 中仍然有效的材料库信息。

发现文档与代码不一致时，以代码和已验证生产环境为准，并同步修正文档。

## 安全边界

- 不写入真实服务器 IP、账号密码、SSH 私钥、Deploy Key、API Key 或 Token；
- 不写入本地敏感文件目录中的具体凭证内容；
- 示例统一使用占位符；
- 不把模型、用户数据、上传结果或原始研究数据加入 Git；
- 不声称平台已经具备尚未验证或尚未实现的功能。

## 验收标准

- 根 README 覆盖用户要求的完整平台、开发、发布、更新、文件用途和模型更新；
- README 中的命令与 Windows 本地环境和 Ubuntu 24.04 服务器一致；
- 旧材料库批处理内容迁移后没有丢失；
- `deploy/README.md` 不再写 Ubuntu 22.04，包含 `libgl1` 和 `bimweb` Git 规则；
- Markdown 链接和 Mermaid 语法可读；
- 文档中不存在真实凭证或服务器地址；
- `.gitignore` 继续排除模型、运行数据和环境文件；
- 完整 `unittest` 测试通过；
- 仅审核过的文档变更被提交并推送到 `origin/main`。
