# 标注工具区域裁剪设计

## 目标

在保留现有整页标注流程的同时，允许用户在同一 PDF 页面上创建多个具名裁剪
区域，例如把同页的“四层”和“五层”分别作为独立训练样本标注和导出。

## 用户流程

1. 用户按现有流程导入 PDF、选择页码并准备页面。
2. 页面准备完成后，用户选择“整页标注”或“创建裁剪区域”。
3. 创建裁剪区域时，用户在原始页面上拖动矩形框，并输入区域名称。
4. 系统显示裁剪预览；用户确认后生成该区域独立的标注目标。
5. 同一 PDF 页面可以继续创建其他区域，并在整页及各区域之间切换。
6. 每个目标独立保存草稿、恢复历史、执行预标注、确认和导出。

整页目标沿用当前页面状态和存储位置。未创建区域的项目行为完全不变。

## 区域身份与坐标

每个区域包含：

- `region_id`：项目内稳定且不可由用户直接修改的标识；
- `name`：用户可见名称，例如“四层”；
- `source_page_number`：一基 PDF 页码；
- `crop_bbox_px`：原始准备页面坐标中的 `[x0, y0, x1, y1]`；
- `created_at` 和 `updated_at`；
- 独立的 `status`、`current_version` 和标注版本链。

矩形必须位于原始页面范围内，宽高均不少于 128 像素，且面积不少于整页面积的
1%。区域之间允许重叠，以支持复杂排版；同一页面上的区域名称不得重复。

## 图像和蒙版处理

- 裁剪从当前页面已经生成的原始分辨率 `render`、`cleaned` 和 `model_view`
  图像执行，不从浏览器截图取样。
- 裁剪后的 `model_view` 使用现有 letterbox 规则独立缩放到 512×512。
- 蒙版画布使用裁剪区域的原始像素尺寸，导出时以最近邻插值生成对应的
  512×512 类别蒙版。
- 墙、窗、门类别编号继续使用 1、2、3，背景为 0。
- 区域坐标和 letterbox 元数据持久化，保证蒙版恢复和导出可复现。

## 存储结构

整页标注继续保存在：

`annotations/<project_id>/page-<page_number>/versions/`

区域标注保存在：

`annotations/<project_id>/page-<page_number>/regions/<region_id>/versions/`

区域准备产物保存在：

`projects/<project_id>/pages/<page_number>/regions/<region_id>/`

项目清单在对应页面下增加 `regions` 映射。读取旧项目时，缺少 `regions`
等价于空映射，不执行数据迁移，也不改写已有整页标注。

## 接口

新增区域资源接口：

- `GET /api/projects/<project_id>/pages/<page>/regions`
- `POST /api/projects/<project_id>/pages/<page>/regions`
- `GET /api/projects/<project_id>/pages/<page>/regions/<region_id>/artifact/<name>`
- `GET|POST /api/projects/<project_id>/pages/<page>/regions/<region_id>/mask`
- `POST /api/projects/<project_id>/pages/<page>/regions/<region_id>/preannotate`
- `POST /api/projects/<project_id>/pages/<page>/regions/<region_id>/confirm`

第一版不提供删除区域，防止误删已完成标注。矩形确认后不可直接修改；用户需要
创建新区域，以保证已有蒙版坐标不被静默改变。

## 导出格式

整页和区域均作为独立样本导出。区域样本增加：

- `source_page_number`
- `region_id`
- `region_name`
- `crop_bbox_px`

区域样本 ID 使用：

`<project_id>-page-<page_number>-region-<region_id>`

训练数据读取器继续只依赖 `image` 和 `mask`，因此无需了解裁剪坐标。导出报告
同时列出 confirmed 整页和 confirmed 区域的数量；同一页面的多个区域分别计数。

## 界面

- 页面准备完成后的工具栏增加“整页”和“裁剪区域”模式。
- 裁剪模式暂时关闭画笔，鼠标拖动显示矩形选择框和宽高。
- 确认区域名称后，左侧页面列表下显示该页的区域子项及状态。
- 当前目标标题明确显示“第16页 / 四层”等信息，防止在错误区域上标注。
- 切换目标前继续使用现有自动保存机制；保存失败时阻止切换。

## 错误处理

- 未准备页面时拒绝创建区域；
- 非有限坐标、越界框、反向框、过小区域和重复名称返回明确错误；
- 任一裁剪产物生成失败时不写入项目清单；
- 保存蒙版时严格校验其尺寸等于区域原始尺寸；
- 导出前重新校验图片、蒙版、SHA-256、类别范围和 confirmed 状态；
- 已确认整页或区域不会因创建其他区域而改变状态。

## 测试

- 存储测试覆盖区域创建、路径约束、版本链和旧项目兼容；
- 服务测试覆盖裁剪像素、512 letterbox、蒙版尺寸和多个区域；
- 接口测试覆盖创建、列出、保存、预标注、确认和无效坐标；
- 导出测试证明同一页两个区域成为两个唯一训练样本并携带裁剪元数据；
- JavaScript 测试覆盖页面坐标换算、矩形规范化和目标切换保护；
- 现有整页标注、导出和训练数据测试必须继续通过；
- 使用包含四、五层的真实 PDF 页面手动验证两个区域可分别标注和导出。

## 实施顺序

1. 先完成多页训练兼容并启动一、二、三层联合训练。
2. 增加区域存储模型和后端裁剪服务。
3. 增加区域接口和导出支持。
4. 增加前端框选、命名、切换和状态显示。
5. 完成自动化测试及真实双区域页面验证。

本阶段只升级标注工具。网站能耗识别若要从同一 PDF 页面只识别某一楼层，仍需
后续加入对应的识别区域选择；本设计不会隐式改变网站识别行为。
