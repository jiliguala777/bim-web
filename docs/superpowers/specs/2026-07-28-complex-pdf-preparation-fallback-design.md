# 复杂 PDF 页面准备超时与栅格回退设计

## 背景

标注工具当前复用网站的 PDF 页面预处理流程。该流程会先通过
`pdfplumber` 提取页面的矢量文字、线段和样式边，再使用 Poppler
渲染页面。对于普通 PDF，这些矢量信息可用于比例尺标定、尺寸线清理和
建筑区域检测；但部分由 CAD 或 iTextSharp 生成的大型 A1 图纸包含大量
复杂矢量对象，解析单页可能长时间占用 CPU。

本次实际文件共 36 页、约 28.7 MB。单独解析页面超过两分钟仍未完成，
用户重复点击后又产生了多条并行准备请求。项目创建成功，但页面准备无法
完成。

人工标注训练只需要生成以下四类像素标签：

- `0`：背景
- `1`：墙
- `2`：窗
- `3`：门

比例尺、实际面积和能耗计算属于模型识别后的能耗平台流程，不应阻塞标注
数据生产。

## 目标

1. 普通 PDF 继续使用现有矢量增强路径。
2. 矢量解析超过 15 秒时可靠终止，并自动转入栅格回退路径。
3. 回退页面仍能生成可标注、可导出和可训练的完整页面产物。
4. 同一项目同一页面不能并行执行多个准备任务。
5. 用户能够明确看到页面正在准备、已经回退或准备失败。
6. 网站识别与标注工具继续复用同一个页面预处理入口。

## 非目标

- 本次不修改模型类别、损失函数或训练策略。
- 本次不在标注工具中计算比例尺、面积或能耗。
- 本次不更换 PDF 解析库。
- 本次不创建后台任务队列、数据库或跨进程作业调度系统。
- 本次不删除用户已经创建的重复项目或任何 PDF、标注和导出数据。

## 方案选择

采用“共享预处理限时矢量解析 + 自动栅格回退”。

未采用以下方案：

- 标注工具永久跳过矢量解析：虽然简单稳定，但会造成网站识别与标注输入
  不一致。
- 全面替换 `pdfplumber`：会增加依赖和迁移风险，也不能证明所有 CAD
  PDF 都能稳定解析。

## 后端架构

### 限时矢量解析

`floorplan_page_pipeline.prepare_pdf_page` 保持为网站和标注工具共同使用的
公共入口，并新增可配置的矢量解析超时参数，默认值为 15 秒。

矢量解析在独立子进程中运行。主进程只等待到超时上限：

- 在 15 秒内成功：继续现有矢量清理、比例尺和 ROI 流程。
- 超过 15 秒：终止并回收子进程，进入栅格回退。
- 子进程异常退出：记录失败原因并进入栅格回退。

必须真正终止超时任务，不能只让 HTTP 请求返回后把解析线程留在后台继续
占用 CPU。

### 栅格回退

回退路径只使用 Poppler 渲染用户选择的单页，默认采用 100 DPI。A1 页面
在该分辨率下仍保留数千像素宽高，足以进行构件骨架标注，并会继续经过：

1. 颜色标记清理；
2. 深色 CAD 预处理；
3. 等比例缩放和 512 模型输入 letterbox；
4. 原图、清理图、模型图、512 预览和预处理元数据写入。

回退路径不执行以下依赖矢量数据的步骤：

- 自动比例尺标定；
- 矢量尺寸线清理；
- 矢量结构支撑掩码；
- 矢量建筑 ROI 检测。

这些缺失不会改变墙、窗、门的类别标签，也不会阻止保存、确认、导出或
训练。

### 回退证据

`preprocessing.json` 和页面准备清单记录稳定、可审计的矢量分析信息：

```json
{
  "vector_analysis": {
    "status": "timed_out",
    "mode": "raster_fallback",
    "timeout_seconds": 15,
    "reason": "vector extraction exceeded 15 seconds"
  }
}
```

`status` 允许值为 `completed`、`timed_out` 或 `failed`。成功路径的
`mode` 为 `vector`，回退路径的 `mode` 为 `raster_fallback`。

回退时比例尺状态保持 `manual_required`，矢量清理证据明确标记为未启用，
不能伪装成成功完成了矢量分析。

## 防止重复准备

`AnnotationService` 在进程内维护受互斥锁保护的页面准备集合，键为
`(project_id, page_number)`。

请求流程为：

1. 原子检查并登记页面键；
2. 如果页面键已存在，立即返回 HTTP 409，提示“该页面正在准备”；
3. 执行共享页面预处理；
4. 无论成功、回退还是异常，都在 `finally` 中移除页面键。

该机制用于阻止同一服务进程内因重复点击、多标签页或重试产生的并行任务。
它不替代现有的“已有标注版本后禁止重新准备”完整性校验。

## 前端交互

点击“准备所选页面”后：

- 立即把页面状态显示为“页面准备中…”；
- 禁用“准备所选页面”按钮、项目选择器和页码选择器；
- 按钮文字改为“正在准备，请勿重复点击…”；
- 请求结束前忽略再次点击；
- 成功后重新加载项目和页面并显示准备结果；
- 回退成功时在检查信息中显示“复杂 PDF 已使用栅格模式准备，可正常标注”；
- 失败时显示后端错误；
- 在 `finally` 中恢复选择器和按钮文字，并根据当前选择重新计算按钮可用性。

本次不实现逐百分比进度条，因为预处理步骤没有稳定、可度量的百分比。界面
只提供准确的忙碌状态和最终结果。

## 错误处理

- 矢量解析超时或解析异常属于可恢复情况，自动回退，不返回失败。
- Poppler 渲染失败、源 PDF 丢失或页面越界属于不可恢复情况，返回清晰错误。
- 重复准备返回 HTTP 409，不创建第二个任务。
- 任何失败都不能写入不完整的页面准备清单。
- 临时图像仍使用现有原子替换方式写入，避免把半写入文件当成有效产物。

## 测试策略

### 单元测试

- 矢量解析在期限内完成时保留现有矢量路径。
- 矢量解析超时时终止工作进程并生成栅格回退产物。
- 矢量解析抛出异常时生成栅格回退产物。
- 回退元数据包含 `timed_out` 或 `failed`、`raster_fallback` 和超时证据。
- 回退产物仍包含原图、清理图、模型图和 512 模型输入。

### API 测试

- 同一项目同一页面的第二个准备请求返回 HTTP 409。
- 第一个请求完成或失败后页面键一定释放。
- 回退成功的页面可继续预标注、保存、确认和导出。

### 前端与浏览器验证

- 准备期间按钮和选择器被禁用，按钮文字发生变化。
- 请求成功、回退或失败后控件恢复。
- 使用本次 36 页实际 PDF 选择一层所在页，只产生一个准备请求。
- 页面在合理时间内进入栅格回退并显示底图，可继续绘制墙、窗、门。
- 浏览器控制台没有新的 JavaScript 错误。

## 成功标准

1. 实际复杂 PDF 不再无限占用 CPU。
2. 点击一次“准备所选页面”后，最迟在矢量超时加单页渲染时间后得到可标注
   页面或明确的 Poppler 错误。
3. 重复点击不能启动并行准备任务。
4. 回退页面可以完成预标注、人工修正、确认和训练数据导出。
5. 普通 PDF 的既有矢量增强行为和现有测试保持通过。
