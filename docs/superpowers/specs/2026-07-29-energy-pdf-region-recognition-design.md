# 能耗平台 PDF 区域识别设计

## 目标

在能耗平台的平面图识别步骤中，为 PDF 增加两种互斥模式：

- 整页识别：保持现有行为。
- 裁剪区域识别：在所选 PDF 页的预览图上拖出一个矩形，只识别该区域。

当前版本每次只允许选择并识别一个区域，不保存命名区域，也不为
PNG、JPG 等图片上传增加裁剪功能。

## 用户流程

1. 用户上传 PDF，平台保存文件并返回页数。
2. 用户选择需要识别的页码，平台加载该页的轻量预览。
3. 用户选择“整页识别”或“裁剪区域识别”。
4. 整页模式下，用户直接开始识别。
5. 裁剪模式下，用户在预览图上拖出矩形。用户可以清除并重新框选。
6. 裁剪框有效时，“开始识别所选区域”按钮才可用。
7. 识别完成后，输入图和叠加图只展示实际识别范围。

切换 PDF 页、重新上传 PDF 或切回整页模式时，平台清除旧裁剪框，
避免把上一页坐标误用于当前页面。

PDF 默认选择“整页识别”，但包括单页 PDF 在内都先显示预览并等待用户
点击识别，不再在上传后立即自动运行模型。

## 前端设计

PDF 页选择卡片增加：

- 页面预览容器；
- “整页识别 / 裁剪区域识别”模式切换；
- 覆盖在预览图上的裁剪画布或选择层；
- 清除裁剪按钮；
- 当前裁剪区域尺寸提示；
- 根据模式变化的识别按钮文案。

裁剪坐标以预览图的原始像素空间保存为
`[x0, y0, x1, y1]`，而不是 CSS 显示尺寸。浏览器缩放、响应式布局和
高 DPI 屏幕不会改变传给后端的坐标。

裁剪框必须：

- 完全位于预览图内；
- 宽、高均不小于 128 像素；
- 面积不小于预览页面积的 1%。

前端复用标注工具 `annotation_tool/static/crop_region.js` 中的坐标归一化
和区域校验规则，避免两套裁剪语义不一致。

## 后端接口

### PDF 页面预览

新增登录保护接口：

`POST /energy/pdf_page_preview`

请求字段：

- `report_number`
- `pdf_upload_token`
- `pdf_page_number`

接口复用已保存的 PDF 和签名上传令牌，校验报告编号及页码。它使用
Poppler 以固定 100 DPI 只渲染所选页面，不运行模型推理或矢量分析。

响应包含：

- JPEG 预览的 Base64 数据；
- `image_size: [width, height]`；
- 页码和总页数。

### 正式识别

扩展现有 `POST /energy/ai_recognize`，新增可选字段：

- `recognition_mode`: `full_page` 或 `crop_region`
- `crop_bbox_px`: JSON 数组 `[x0, y0, x1, y1]`
- `crop_preview_size`: JSON 数组 `[width, height]`

整页模式及未提供新字段的旧请求继续走现有流程。

区域模式要求请求来自已暂存 PDF；普通图片请求携带区域模式时返回
400。后端重新校验数组长度、数值范围、最小尺寸和最小面积比例。

## 坐标映射与图像处理

轻量预览和正式预处理可能采用不同渲染尺寸。后端按两个方向分别计算：

```text
scale_x = prepared_width / preview_width
scale_y = prepared_height / preview_height
```

然后将预览裁剪框映射到正式页面，左上角向下取整、右下角向上取整，
最后限制在页面边界内。

PDF 仍先执行现有整页准备流程，以保留：

- 自动比例尺提取；
- 尺寸标注清理；
- 矢量结构支撑；
- 建筑范围检测。

映射完成后，同步裁剪以下像素对齐数据：

- 原始渲染图；
- 清理后的模型输入图；
- 尺寸清理掩膜；
- 矢量结构支撑掩膜。

原有 `inference_roi` 与裁剪框求交，再平移到裁剪图局部坐标。如果没有
有效交集，则使用整个裁剪区域作为推理范围。拓扑修复、闭合房间提取和
面积计算全部在裁剪后的局部坐标中进行。

比例尺是“米/像素”，正式裁剪没有重采样，因此继续使用整页获得的
`scale_m_per_px`。即使裁剪区域本身不包含尺寸线，也能继续计算面积。

## 结果和持久化

区域模式返回的：

- `images.original`
- `images.overlay`
- `image_size`
- 房间多边形和构件几何

都使用裁剪后的局部坐标。

`recognition.json` 额外保存：

- `recognition_mode`
- `pdf_page_number`
- `crop_bbox_page_px`：正式 PDF 页面像素空间中的裁剪框
- `crop_bbox_preview_px`：用户在预览像素空间中的裁剪框
- `crop_preview_size`

后续手动比例尺标定继续使用裁剪结果的局部坐标，不改变现有接口。

## 错误处理

以下情况返回 400，并提供可直接展示给用户的错误信息：

- 上传令牌无效或不属于当前报告；
- 页码越界；
- 区域模式用于非 PDF 文件；
- 裁剪框或预览尺寸不是有限数字数组；
- 裁剪框越界、过小或面积不足；
- 坐标映射后没有有效区域。

预览或识别失败时，前端保留当前页码和合法裁剪框，允许用户直接重试。

## 测试

自动测试覆盖：

- 页面预览接口只渲染指定页并返回真实图片尺寸；
- 无新字段的整页请求保持兼容；
- 区域请求正确映射不同预览尺寸和正式渲染尺寸；
- 原图、清理图、结构支撑掩膜及推理范围同步裁剪；
- 整页比例尺保留并应用到区域房间面积；
- 区域元数据写入 `recognition.json`；
- 非 PDF、越界、过小及畸形区域被拒绝；
- 前端包含模式切换、预览、拖框、重置和请求字段；
- 切换页码或重新上传时清除旧裁剪状态。

最后使用包含四层和五层的真实 PDF 页面做人工验证：分别框选四层和
五层，确认两次结果只包含所选楼层，面积和比例尺可用，整页识别仍可用。
