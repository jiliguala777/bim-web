# 标注训练工具独立仓库拆分设计

日期：2026-07-29

## 目标

将 PDF 标注工具、模型训练和 ONNX 导出流程从 `jiliguala777/bim-web`
的待合并变更中拆出，发布到新的私有仓库
`jiliguala777/bim-annotation-training`。

GitHub 上现有的 `bim-web/main` 不做直接改动。当前草稿 PR #1 经过整理后，
只保留能耗平台运行、识别和展示相关变更。

## 最终仓库边界

### `jiliguala777/bim-web`

保留：

- 能耗平台 Flask 服务和页面。
- PDF 整页识别与单区域裁剪识别。
- 能耗平台运行所需的 PDF 页面准备、ONNX 推理和拓扑修复模块。
- 与上述功能直接相关的测试和文档。

从草稿 PR #1 移除：

- `annotation_tool/`。
- `training/`。
- 标注工具和训练流程专属测试。
- 标注、训练和实验流程专属说明。
- 仅用于训练的 ONNX 导出代码。

### `jiliguala777/bim-annotation-training`

包含：

- PDF 标注 Web 工具、区域裁剪、版本存储和数据导出。
- 多样本训练、损失函数、评估和实验流程。
- PyTorch 模型导出 ONNX 的工具。
- 标注工具运行所需的 PDF 页面准备和 ONNX 推理模块。
- 独立 README、依赖文件、启动脚本和相关自动化测试。

不包含：

- 模型权重。
- 标注项目数据和导出的训练样本。
- 训练检查点、评估图片和实验产物。
- 上传文件、日志、本地数据库和凭证。

## 公共代码策略

采用独立复制必要公共模块的方式，不建立第三个公共仓库，也不让新仓库依赖
`bim-web` 的本地路径。

PDF 页面准备和 ONNX 推理模块会在两个仓库中分别保留一份：

- `bim-web` 中的版本服务于线上识别。
- `bim-annotation-training` 中的版本服务于本地标注、预览和模型校验。

拆分时只复制当前已验证实现，不做额外抽象或功能重构。以后如公共代码频繁变化，
再单独评估提取共享 Python 包。

## 实施流程

1. 以当前已验证代码为来源，建立独立的临时工作目录。
2. 复制标注、训练、导出及必要公共模块和测试。
3. 重写新仓库 README、依赖说明和启动命令，移除对 `G:\bim-web` 的假设。
4. 为新仓库配置 `.gitignore`，排除模型、数据、实验产物和敏感文件。
5. 运行标注、存储、PDF 处理、训练和导出测试。
6. 创建私有 GitHub 仓库 `jiliguala777/bim-annotation-training`，发布初始
   `main`。
7. 回到 `bim-web` 的 `agent/recent-bim-updates` 分支，删除标注训练专属内容，
   更新 README 和测试引用。
8. 运行完整的 `bim-web` 测试，并更新远程分支和草稿 PR #1。
9. 核对 PR #1 文件清单，确保它只包含能耗平台相关内容，再将其标记为可审查。

## 草稿 PR 的含义

草稿 PR 是已上传但尚未合并的候选改动。整理 PR #1 不会直接改动
GitHub 的 `bim-web/main`。只有后续明确执行合并，`main` 才会更新。

本次拆分完成后：

- 新标注训练仓库直接拥有自己的 `main`。
- `bim-web` 的平台改动继续通过 PR #1 等待合并。

## 验证标准

### 新仓库

- 标注项目创建、PDF 页面准备、裁剪、保存和导出相关测试通过。
- 训练数据加载、损失函数、训练、评估和 ONNX 导出测试通过。
- README 中的安装、启动和训练命令不引用 `bim-web` 本地路径。
- Git 历史和文件清单中不存在模型权重、标注数据或凭证。

### `bim-web`

- 完整 Python 测试通过。
- PDF 裁剪识别和前端状态测试通过。
- PR #1 不含 `annotation_tool/`、`training/` 和它们的专属测试。
- 能耗平台仍保留运行必需的 PDF、ONNX 和拓扑修复模块。

## 失败保护与回退

- 新仓库测试未通过时不创建或不推送发布提交。
- 新仓库创建或推送失败时，不改动 `bim-web/main`。
- `bim-web` 完整测试未通过时，不更新 PR #1。
- 两个仓库均只显式暂存计划内文件，不使用覆盖所有未跟踪文件的批量暂存。
- 现有草稿 PR 分支保留旧提交历史，因此在需要时可以检查拆分前版本。
