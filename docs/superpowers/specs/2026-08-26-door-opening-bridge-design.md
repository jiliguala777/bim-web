# PDF 门洞桥接与外轮廓连续性设计

## 目标

在原生矢量 PDF 平面图中，门洞或窗洞不能使外轮廓后续墙体失去识别依据。系统应从原生曲线、短线、两侧墙端点和模型概率联合识别开口，并允许已证实的开口桥接外轮廓。

## 范围与约束

- 仅处理位于候选外轮廓上的轴对齐开口。
- 墙体必须仍由 PDF 原生结构直线支撑；系统不凭空生成长墙。
- 高置信度门、窗可进入门窗面积统计。
- 低置信度开口只用于外轮廓闭合，不能自动扣除门窗面积。
- 无两侧墙端点、无原生开口证据、超出尺度范围或位于尺寸标注区域的缺口保持未解决状态。

## 数据流

```text
原生 PDF 路径
  ├─ 正交结构直线（现有）
  └─ 曲线/短线开口证据（新增）
             ↓
候选外墙与缺口
             ↓
模型门线/窗线概率 + 原生开口证据
             ↓
door / window / pending_opening / unresolved
             ↓
外轮廓拓扑与能耗几何
```

## 组件设计

### 原生开口证据

扩展原生 PDF 页面契约，保存可追溯的曲线边界框、端点、线宽和颜色。对于每个外墙缺口，提取其局部原生证据：

- 门弧：曲线边界框覆盖缺口，且至少一个端点接近缺口端点；
- 窗短线：缺口附近存在与墙轴平行的短线组；
- 两侧墙：缺口已有两个无歧义的共线外墙端点。

曲线和短线证据不直接生成墙，只为开口候选提供证据。

### 开口判定

- `door`：模型门线和端点满足阈值，或门弧与两侧墙端点提供强原生证据。
- `window`：模型窗线和端点满足阈值，或短平行线组与两侧墙端点提供强原生证据。
- `pending_opening`：两侧墙端点和至少一种原生开口证据存在，但不足以可靠区分门与窗。
- `unresolved`：不满足上述安全条件。

每种结果均记录证据、置信度和原因码。

### 外轮廓与能耗规则

`door`、`window` 和 `pending_opening` 都可作为拓扑桥接段，使后续原生外墙继续参与闭合候选。只有 `door`、`window` 写入门窗宽度与面积扣除输入；`pending_opening` 仅保留宽度和待确认状态。

### 可视化与保存

综合识别图固定保存为 `pdf_component_overlay.png`：绿为墙、蓝为门、青为窗、橙为待确认开口、红虚线为未解决缺口。门窗和待确认开口均在 JSON 工件中保留来源与理由。

## 错误处理

- 非矢量 PDF、曲线解析失败或缺少模型时，不产生自动开口。
- 证据不完整时降级为 `pending_opening` 或 `unresolved`，不影响已识别墙体。
- 闭合失败仍禁止将结果用于能耗面积计算，直到用户确认有效外轮廓。

## 验证

- 原生曲线可被提取并映射到页面像素坐标。
- 门弧可将无模型门证据的合格缺口判为门或待确认开口。
- 待确认开口可以闭合拓扑，但不会计入门窗面积。
- 无门弧、无短线或无两侧墙端点的缺口不会被桥接。
- 在真实图纸回放中，左上拐角和右上缺失段能保持后续墙体连续。
