# 外门弧辅助恢复外墙连续性设计

日期：2026-08-26

## 背景

当前 PDF 融合流程先筛选外墙，再从相邻外墙之间枚举缺口，最后在缺口中识别门窗。这种顺序要求门洞两侧墙段都已经通过外墙筛选。

真实图纸中，门洞后的墙段可能因为模型墙体概率或 PDF 原生线条样式不足而保持为 `uncertain`。此时左侧区域不会生成外墙缺口；右上角可能把多段墙体和多个开口合并为一个大缺口。虽然 PDF 中存在真实门弧，门分类器也没有可匹配的局部缺口。

平台当前只需要识别建筑外轮廓上的门窗。内部墙体和内部房间不属于本次范围。

## 目标

- 保持现有墙体和窗识别逻辑不变。
- 在外轮廓拓扑生成前独立识别外门弧。
- 利用外门弧连接已确认外墙与具有 PDF 直线证据的相邻不确定墙段。
- 连接后重新枚举外轮廓缺口并识别门窗。
- 只有确认的外门计入门宽和后续门面积扣除。
- 证据不足的门弧只作为待确认开口参与局部连续性，不扣门面积。

## 非目标

- 不识别或统计内门、内窗。
- 不修改新模型训练、权重或推理脚本。
- 不放宽所有不确定墙段的外墙准入条件。
- 不使用门弧跨越没有任何 PDF 墙线证据的大面积区域。
- 不由 Codex 执行最终真实图纸验收；用户在平台自行验证。

## 方案选择

采用“墙体与窗照旧识别，门弧独立检测，门弧辅助恢复墙段，再重建外轮廓”的顺序。

不采用以下方案：

- 仅在既有缺口中继续放宽门弧阈值：无法处理没有形成局部缺口的左侧墙段。
- 主要依赖模型门概率：当前真实图纸的门概率不足以稳定恢复外门。
- 全局提升不确定墙段：容易把标注线、家具线和内部构件带入外轮廓。

## 数据流

```text
PDF 原生线条 + 模型概率
          |
          v
现有墙体融合与窗识别（保持不变）
          |
          +--------------------------+
          |                          |
          v                          v
已确认外墙种子                  开放门弧候选
          |                          |
          +------------+-------------+
                       v
          门弧邻域墙段恢复
          - 已确认外墙
          - 有 PDF 直线证据的 uncertain 墙段
                       |
                       v
              重新枚举外轮廓缺口
                       |
                       v
       确认门 / 待确认开口 / 普通小缺口补线
                       |
                       v
              外轮廓、面积、周长、门宽
```

## 组件设计

### 1. 门弧候选

原生 PDF 提取继续只保留开放 Bézier 曲线。门弧候选必须携带真实路径起点、终点、外接框和曲线路径命令，不再使用外接框角点代替曲线端点。

门弧候选首先只表示“可能的开口证据”，不直接成为门。

### 2. 外轮廓邻域过滤

门弧只在已确认外墙种子形成的外侧边界带附近参与恢复。候选必须满足：

- 门弧至少一个真实端点接近已确认外墙；
- 门弧的尺度符合局部门洞，而不是文字、轴号或大范围图形；
- 门弧对应区域不位于已确认建筑内部深处；
- 闭合曲线、没有 Bézier 命令的图形和页面边框不能进入门弧候选。

### 3. 门弧邻域墙段恢复

门弧附近的 `uncertain` 线段只有同时满足以下条件才可升级为“门弧恢复墙段”：

- 线段具有 PDF 原生直线证据；
- 线段与相邻已确认外墙同方向且位于同一外墙带；
- 线段端点靠近门弧真实端点或门洞另一侧墙端；
- 恢复不会穿过建筑内部形成捷径；
- 线段长度和位置保持在局部门弧邻域内。

恢复结果使用独立原因码，不能改写原始融合判定，便于复核和回退。

### 4. 二次缺口与门分类

恢复墙段加入外墙集合后，重新枚举缺口。

- 门弧与两侧墙端形成明确局部缺口：确认外门，显示蓝色，记录门宽。
- 门弧存在但只有一侧墙体关系明确：生成橙色待确认开口，可参与局部闭合，不记录门宽。
- 没有门弧证据的小缺口：沿用普通小缺口直线修补规则。
- 大缺口或存在多个竞争拓扑：保持红色未解决状态。

### 5. 能耗数据边界

- 建筑面积与周长使用最终闭合外轮廓。
- 只有 `accepted_openings` 中的外门、外窗记录宽度并参与面积扣除。
- `pending_openings` 和普通补线不参与门窗面积扣除。
- 门窗高度继续由后续能耗页面设置。

## 产物与显示

综合识别图继续使用：

- 绿色：确认外墙和门弧恢复墙段；
- 蓝色：确认外门；
- 青色：确认外窗；
- 橙色：待确认开口或普通补线；
- 红色：未解决缺口。

诊断 JSON 增加门弧恢复墙段的来源门弧、原始候选墙段、原因码和是否参与最终外轮廓。平台保存文件夹继续保留综合识别图。

## 失败与安全处理

- 找不到已确认外墙种子时，不执行门弧墙段恢复。
- 一个门弧匹配多个相互竞争的外墙方向时，保持待确认或未解决。
- 恢复后出现自交、多边形异常或面积异常时，拒绝该恢复结果。
- 无法闭合时保持 `exterior_not_closed`，不能用于能耗计算。
- 所有新增恢复均保留可追踪原因码，不静默修改原始识别结果。

## 测试与验收

自动化测试覆盖：

- 开放 Bézier 门弧保留真实端点；
- 闭合柱形、矩形和文字轮廓不能成为门；
- 外门弧可连接确认墙段与有 PDF 证据的不确定墙段；
- 内部门弧不参与外轮廓恢复；
- 只有一侧墙证据时生成待确认开口且不扣门面积；
- 竞争拓扑和大缺口保持未解决；
- 门弧恢复后重新枚举缺口并生成确认门；
- 现有墙体、窗、面积、周长和门窗扣除测试不回归。

完成代码与自动化回归后，由用户在能耗平台使用真实图纸执行最终视觉验收。
