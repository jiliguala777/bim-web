## 4. 当前网站如何逐步计算

## 4.1 派生人数、运行小时和新风量

人数：

```text
N = 建筑面积 ÷ 人均占用面积
  = 639.48 ÷ 10
  = 63.948 人
```

新风量：

```text
V_fresh = N × 人均新风量
        = 63.948 × 30
        = 1918.44 m³/h
```

年运行小时和运行比例：

```text
H_op = 12 × 250 = 3000 h/a
f_op = 3000 ÷ 8760 = 0.342466
```

渗透风量：

```text
V_inf = 面积 × 层高 × ACH
      = 639.48 × 6.0 × 0
      = 0 m³/h
```

因此层高已经保存并参与公式，但被 `ACH=0` 乘为零。

## 4.3 HDD/CDD 修正

当前西安气候库给出：

```text
HDD18 = 2400 K·d
CDD26 = 200 K·d
```

代码按设定温度进行线性修正：

```text
HDD_adj = max[0, HDD18 + (T_heat - 18)×120]
CDD_adj = max[0, CDD26 + (26 - T_cool)×90]
```

本次 `T_heat=18℃`、`T_cool=26℃`，所以：

```text
HDD_adj = 2400 K·d
CDD_adj = 200 K·d
```

## 4.4 全年供暖热需求

### 4.4.1 围护结构供暖需求

```text
Q_heat,envelope
  = UA × HDD_adj × 24 ÷ 1000
  = 515.3356 × 2400 × 24 ÷ 1000
  = 29,683.331 kWh_th/a
```

### 4.4.2 新风供暖显热需求

新风等效热容量流率：

```text
UA_fresh
  = 0.335 × V_fresh × (1 - η_HR)
  = 0.335 × 1918.44 × (1 - 0)
  = 642.677 W/K
```

按年运行比例折减：

```text
Q_heat,fresh
  = UA_fresh × HDD_adj × 24 ÷ 1000 × f_op
  = 642.6774 × 2400 × 24 ÷ 1000 × 0.342466
  = 12,677.472 kWh_th/a
```

### 4.4.3 渗透风供暖需求

```text
UA_inf = 0.335 × V_inf = 0 W/K
Q_heat,inf = 0 kWh_th/a
```

### 4.4.4 供暖热需求合计

```text
Q_heat,total
  = 29,683.331 + 12,677.472 + 0
  = 42,360.803 kWh_th/a
```

该值是建筑和新风需要得到的年度热量，不是设备耗电量。

## 4.5 当前制冷计算：可复算，但四层不适用

当前代码仍对四层计算制冷。围护结构传热部分为：

```text
Q_cool,transmission
  = 515.3356 × 200 × 24 ÷ 1000
  = 2,473.611 kWh_th/a
```

制冷太阳得热采用：

```text
Q_solar,o
  = A_window,o × SHGC × 遮阳系数 × 年太阳辐照量
    × 朝向系数 × CDD/(CDD+HDD)
```

| 朝向 | 朝向系数 | 太阳得热 (kWh_th/a) |
|---|---:|---:|
| 东 | 0.78 | 56.722 |
| 南 | 1.00 | 12.237 |
| 西 | 0.86 | 70.357 |
| 北 | 0.38 | 4.650 |
| **合计** | — | **143.965** |

所以：

```text
Q_cool,envelope = 2,473.611 + 143.965
                  = 2,617.576 kWh_th/a

Q_cool,fresh
  = 642.6774 × 200 × 24 ÷ 1000 × 0.342466
  = 1,056.456 kWh_th/a

Q_cool,total
  = 2,617.576 + 1,056.456 + 0
  = 3,674.032 kWh_th/a
```

以上过程能解释数据库中的制冷结果，但文化宫四层原设计没有供冷，因此该结果不能作为四层实际年度制冷需求或原设计用能。

## 4.6 等效峰值校核

当前峰值使用围护结构、新风和渗透风的总设计 UA：

```text
UA_design = 515.3356 + 642.6774 + 0
          = 1158.013 W/K
```

供暖等效峰值：

```text
P_heat,eq
  = UA_design × [18 - (-5)] ÷ 1000
  = 1158.013 × 23 ÷ 1000
  = 26.634 kW_th
```

制冷等效峰值：

```text
P_cool,eq
  = UA_design × (34.9 - 26) ÷ 1000
  = 1158.013 × 8.9 ÷ 1000
  = 10.306 kW_th
```

这里没有进行逐时动态模拟，也没有包含严格设计热负荷中的热桥、外门开启、高度附加、间歇附加等修正。因此 `26.634 kW_th` 只能与 `39.43 kW` 做数量级观察，不能称为同口径结果，更不能通过随意调整 ACH 或效率强行拟合。

```text
EUI = 76,399.242 ÷ 639.48
    = 119.471 kWh/(m²·a)
```

仅剔除不适用制冷用电的算术对照：

```text
E_total,no-cooling = 76,399.242 - 1,597.405
                   = 74,801.837 kWh/a

EUI_no-cooling = 74,801.837 ÷ 639.48
               = 116.973 kWh/(m²·a)
```

该对照只修正供冷口径，没有修正气象、ACH、运行时间、系统效率或内部用能假设，所以不能视为最终预测值。

## 8. 建议的改进顺序

### 优先级 0：先修正四层供冷口径

将四层制冷系统改为“无制冷”，或把制冷服务面积设为 0。重新计算后应确认：

- 供暖热需求保持正常；
- 制冷设备用电为 0 或明确显示“不适用”；
- 不再把四层年度制冷结果与一层局部空调设计冷负荷比较。

### 优先级 1：核实对供暖影响最大的项目参数

优先从暖通图纸、设备表和运营资料中取得：

1. 实际渗透风或可接受的 ACH 依据；
2. 外门面积、U 值和开启情况；
3. 新风系统是否存在热回收及效率；
4. 四层实际人员、新风量和运行时间；
5. 真实供暖系统形式及季节性能。

### 优先级 2：核实非暖通用电参数

取得实际 LPD、EPD、照明控制、生活热水开放日和热水设备效率。当前照明、插座设备和生活热水合计占比较大，通用默认值会显著影响总用电。

### 优先级 3：引入运城逐日或逐小时气象

短期可从逐小时气象计算运城实际 HDD/CDD；进一步应逐小时使用干球温度、湿度、太阳直射/散射辐射和风速。若仍把逐小时数据压缩成固定 HDD/CDD，精度提升会受限。

### 优先级 4：升级为逐小时动态模型

在参数和冷热服务区域稳定后，再考虑逐小时 RC 模型或 EnergyPlus，以处理：

- 建筑热惰性和室温回落；
- 人员、照明、设备和太阳得热的逐时耦合；
- 新风潜热；
- 热泵 COP 随室外温度和部分负荷变化；
- 房间级供暖/制冷分区和峰值时刻。

## 9. 最终结论

当前网站已经建立了可复现的“围护结构年度需求 + 新风显热 + 渗透风 + 设备效率 + 照明/设备/热水”的年度计算链。文化宫四层的人工围护几何和供暖计算公式可以稳定复算，但结果仍明显依赖通用假设。

现阶段最需要处理的不是用任意参数让 `26.634 kW_th` 接近 `39.43 kW`，而是依次修正供冷范围、核实 ACH 和外门、确认运行与供暖系统、替换运城气象，并逐步增加动态热过程。完成这些工作后，年度供暖需求和全年用电才具备更强的项目可信度。
